## 配置和运行边界

应用仍只读取一个显式选择的完整 TOML，没有环境变量回退或第二文件叠加。公开的 `prod.toml`
是不可直接启动的模板。真实部署配置必须位于仓库外，并通过原有 `--config` 或单一只读挂载交付；
不得进入 Docker build 参数或镜像层。公开示例默认关闭 Memory/能力索引的外部连接，仅调整
配置默认值，不新增向量数据库功能。

原有本地配置副本位于忽略的 `backend/.local-config/`：目录权限 0700，文件权限 0600，且从
Docker 构建上下文排除。需要继续使用已有本地数据库时，应显式选择匹配的配置，或单独更新本地
角色密码。修改初始化 SQL 不会更改已有 PostgreSQL 数据卷，不应为此删除数据卷。

`scripts/quality/check_secrets.py` 已接入根检查，检查可发布文件及 ZIP 成员中的常见凭据模式，
并强制三套跟踪 TOML 仅含明确的公开占位值。扫描不打印匹配值。它是启发式防线，无法保证检测
任意供应商凭据、个人数据或语义上的私有内容，也不扫描/清理 Git 历史。调用方仍不得记录原始
私有 prompt、完整模型输出或任意业务对象。

## 发布范围和历史

新 GitHub 仓库使用独立目录中的初始快照，分支为 `main`，不携带原仓库的 commit、tag、远端或
reflog。原工作区及旧历史保留；后续 GitHub 开发应使用独立的新检出目录，不能从旧历史直接推送。

公开快照仅含 Parrot 自有工程文件。`skyler/` 迁移来源、独立的 `deepseek-harness/` 仓库、IDE
配置、私有配置备份、日志、依赖和运行产物保留在本地，不上传。没有改写或删除 `skyler/` 文件。
原始 9 个配置敏感值与可发布文件逐值比对，命中数为 0；ZIP 内容同时纳入检查。

旧配置值在原仓库已有历史版本中存在；本次文件脱敏及新快照上传不会撤销这些凭据，也不会清理
原远端、其他克隆、旧日志、构建缓存或镜像层。必须由资源所有者完成以下操作：

1. 在对应服务撤销或轮换对象存储、模型、数据库及其他已提交账户的旧值，并核查访问记录。
2. 轮换 session pepper 并使旧会话失效。已有数据环境更换 credential encryption key 前，先完成
   凭据解密重加密和恢复验证，不能直接丢弃旧 key。
3. 在协调其他使用者后独立清理原仓库历史、引用和制品；不要将旧历史合并或强推到新公开仓库。
