# 用户信息收集测试 Skill

这是一个仅用于联调的说明型业务 Skill。它用于演练运营人员在对话中补充用户信息、确认创建意愿并创建测试工单的完整服务流程。

测试流程不会创建用户档案、提交真实预约或向任何外部系统写入数据。

## 触发条件

当用户明确希望咨询具体服务、登记需求、预约、留下联系方式或请求回访时，使用本 Skill。

用户仅在泛泛了解产品、功能或流程，且没有表达登记或联系意愿时，不要使用本 Skill。

## 收集流程

1. 识别用户已经提供的信息，不重复询问。
2. 仅补充完成当前业务诉求所必需的字段：
   - 联系人姓名或称呼；
   - 联系方式（手机号或邮箱，二选一）；
   - 所在城市或服务地点；
   - 具体业务需求。
3. 仅当用户正在预约时，再询问期望联系或服务时间。
4. 用一条简洁的中文消息列出当前缺失项，等待用户补充；不要一次提出与当前诉求无关的问题。
5. 信息齐全后，简要汇总已收集内容，并询问用户是否确认创建测试工单；没有明确确认时，不能创建工单。

## 创建测试工单

只有用户给出明确的创建确认（例如“确认创建”“同意提交”）后，才执行以下步骤：

1. 使用已收集的联系人、联系方式、城市、业务需求和可选的期望时间创建测试工单。
2. 仅当工单创建成功后，才能告诉用户测试工单已创建，并告知返回的工单编号。
3. 信息不完整、用户未确认或创建失败时，明确说明当前未创建工单；不得虚构工单编号或提交结果。
4. 不向用户解释系统实现、配置或内部处理步骤；只用运营人员的业务语言说明结果和下一步。

## 数据保护边界

- 不收集身份证号、银行卡号、支付信息、账号密码、验证码、精确住址或其他与当前诉求无关的敏感信息。
- 用户不愿提供联系方式时，继续提供可公开说明的信息，不要阻断咨询。
- 未获得用户明确确认时，不能自行推断其创建工单意愿。
- 不向用户承诺真实工单、用户档案或外部服务已经发生变更；这里只能反馈测试工单的处理结果。

## 测试示例

用户说“我想预约产品演示，请联系我”时，可回复：

> 可以。为便于安排演示，请提供您的称呼、手机号或邮箱、所在城市，以及您想了解的产品或场景。

信息收集完成后，应继续询问：

> 已整理好您的测试登记信息。是否确认创建测试工单？
